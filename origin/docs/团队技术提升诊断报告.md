## 二、问题清单 (按优先级)

### P0 — 紧急 (安全/数据丢失风险)

#### 1. API 密钥硬编码暴露
- **文件**: `src/components/EarthquakeMap.vue` 第 513-514 行
- **问题**: 高德地图 API Key (`9771b6c463e702fa00e2602f11b2f7f8`) 和安全密钥 (`eb75f9c1522697027bc209a5118312bc`) 直接写在源码中
- **风险**: 密钥泄露后可被恶意调用，产生费用
- **修复方案**:
  ```bash
  # origin/.env
  VUE_APP_AMAP_KEY=your_key_here
  VUE_APP_AMAP_SECURITY_CODE=your_code_here
  ```
  ```javascript
  // EarthquakeMap.vue
  window._AMapSecurityConfig = {
    securityJsCode: process.env.VUE_APP_AMAP_SECURITY_CODE,
  };
  AMapLoader.load({
    key: process.env.VUE_APP_AMAP_KEY,
  })
  ```
  **注意**: `.env` 文件必须加入 `.gitignore`，并在 `.env.example` 中提供占位符

#### 2. 硬编码 macOS 绝对路径
- **文件**: `src/main.ts` 第 7 行
- **问题**: `/// <reference types="/Users/wujunfeng/GrassPillow.github.io/a-origin/src/router/index.ts" />`
- **风险**: 在任何非该开发者的机器上编译失败
- **修复方案**: 删除该行。如果是为了类型提示，应在 `tsconfig.json` 的 `paths` 中配置 `@/*` 别名

#### 3. v-html XSS 风险
- **文件**: `src/views/BlogPostView.vue` 第 41 行
- **问题**: `v-html="post.content"` 直接渲染未净化的 HTML 字符串
- **风险**: 如果博客内容来源变为用户输入，可导致 XSS 攻击
- **修复方案**:
  ```bash
  npm install dompurify
  ```
  ```javascript
  import DOMPurify from 'dompurify';
  const sanitizedContent = computed(() => 
    DOMPurify.sanitize(post.value.content)
  );
  ```
  模板中改用 `v-html="sanitizedContent"`

#### 4. 生产构建跳过类型检查
- **文件**: `vue.config.js`
- **问题**: `config.plugins.delete('fork-ts-checker')` 在生产环境禁用了类型检查
- **风险**: 类型错误不会阻断构建，可能带入生产环境
- **修复方案**:
  - 安装缺失的类型包: `npm install -D @types/node`
  - 解决类型错误而非跳过检查
  - 在 `package.json` 中添加: `"type-check": "vue-tsc --noEmit"`
  - 逐步恢复 `fork-ts-checker`，先修复现有类型错误

#### 5. deploy.sh 无错误中断
- **文件**: `deploy.sh`
- **问题**: `npm run build` 失败后脚本继续执行文件复制操作
- **风险**: 将旧的/不完整的构建产物部署到线上
- **修复方案**:
  ```bash
  #!/bin/bash
  set -euo pipefail  # 添加到脚本开头
  ```

### P1 — 重要 (架构/可维护性)

#### 6. TypeScript 名不副实
- **现状**: 项目声称使用 TypeScript，但:
  - 所有 14 个 `.vue` 文件的 `<script>` 均无 `lang="ts"`
  - 4 个 composables 全部是 `.js` 文件
  - 仅 `main.ts` 和 `router/index.ts` 两个文件是 `.ts`
- **影响**: 无法享受类型安全、IDE 智能提示大打折扣
- **迁移策略**: 逐文件迁移，优先迁移 composables（影响面最小），再迁移组件
  ```javascript
  // useTheme.js -> useTheme.ts
  import { ref, readonly, watch } from 'vue';
  
  type Theme = 'light' | 'dark' | 'system';
  const theme = ref<Theme>('system');
  const isDark = ref<boolean>(false);
  // ...
  ```

#### 7. 组件编写模式三种混用
- **现状**:
  - `<script setup>` (无 lang="ts") — BlogPostView, BookListView, Toast, BookCard 等
  - Options API — AIView (`export default { data, methods, mounted }`)
  - `defineComponent` + `setup()` — DataTable
- **标准**: 统一使用 `<script setup lang="ts">`
- **迁移优先级**: 先迁移 Options API 组件（AIView），再迁移 defineComponent（DataTable）

#### 8. window.$toast 全局变量反模式
- **文件**: `src/components/Toast.vue` + `src/composables/useToast.js`
- **问题**:
  - 通过 `window.$toast` 全局对象传递状态
  - `useToast.js` 有 100ms 重试逻辑处理竞态条件 — 脆弱
  - `onUnmounted` 中 `delete window.$toast` 可能导致其他组件调用失败
- **修复方案**: 引入 Pinia 或使用 provide/inject
  ```javascript
  // stores/toast.ts
  import { defineStore } from 'pinia';
  
  interface ToastItem {
    id: number;
    message: string;
    type: 'success' | 'error' | 'warning' | 'info';
  }
  
  export const useToastStore = defineStore('toast', () => {
    const toasts = ref<ToastItem[]>([]);
    const show = (message: string, type: ToastItem['type'] = 'info') => {
      const id = Date.now();
      toasts.value.push({ id, message, type });
      setTimeout(() => remove(id), 3000);
    };
    const remove = (id: number) => {
      toasts.value = toasts.value.filter(t => t.id !== id);
    };
    return { toasts, show, remove };
  });
  ```

#### 9. parseCSV 重复实现
- **文件**: `AIView.vue` (第 119-155 行) 和 `BookListView.vue` (第 201-255 行)
- **问题**: 几乎完全相同的 CSV 解析逻辑被复制了两份
- **修复方案**:
  ```javascript
  // src/utils/csv.ts
  export function parseCSV(text: string): string[][] {
    const rows: string[][] = [];
    let current: string[] = [];
    let field = '';
    let inQuotes = false;
    
    for (let i = 0; i < text.length; i++) {
      const char = text[i];
      if (inQuotes) {
        if (char === '"') {
          if (text[i + 1] === '"') { field += '"'; i++; }
          else inQuotes = false;
        } else field += char;
      } else {
        if (char === '"') inQuotes = true;
        else if (char === ',') { current.push(field); field = ''; }
        else if (char === '\n') {
          current.push(field); rows.push(current);
          current = []; field = '';
        } else field += char;
      }
    }
    if (field || current.length) { current.push(field); rows.push(current); }
    return rows.filter(row => row.some(cell => cell.trim()));
  }
  ```

#### 10. 路由缺少 404 兜底
- **文件**: `src/router/index.ts`
- **问题**: 没有 catch-all 路由，访问不存在的路径显示空白页

## 三、团队技术规范建议

### 3.1 组件编写规范

```vue
<!-- 标准组件模板 -->
<script setup lang="ts">
import { ref, computed, onMounted } from 'vue';
import type { PropType } from 'vue';

// Props 带类型
interface BookItem {
  id: number;
  title: string;
  author: string;
  coverColor: string;
  category: string;
}

const props = defineProps({
  book: {
    type: Object as PropType<BookItem>,
    required: true,
  },
});

// Emits 带类型
const emit = defineEmits<{
  (e: 'select', id: number): void;
  (e: 'delete', id: number): void;
}>();

// 响应式状态
const isLoading = ref(false);

// 计算属性
const displayTitle = computed(() => props.book.title.toUpperCase());

// 方法
const handleSelect = () => {
  emit('select', props.book.id);
};

// 生命周期
onMounted(() => {
  // 初始化逻辑
});
</script>

<template>
  <div class="book-card" @click="handleSelect">
    <h3>{{ displayTitle }}</h3>
  </div>
</template>

<style scoped>
.book-card {
  /* 使用 CSS 变量而非硬编码值 */
  background: var(--color-bg-secondary);
  color: var(--color-text-primary);
  border-radius: var(--border-radius-lg);
}
</style>
```
